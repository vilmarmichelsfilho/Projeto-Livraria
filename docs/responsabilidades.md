O sistema mantém quatro entidades conforme o planejamento. Como o enunciado menciona equipes de cinco a seis pessoas, esta divisão ainda depende de orientação do professor para os integrantes adicionais. Não atribuir a eles somente documentação, testes, cadastro ou exclusão e considerar o requisito atendido.

Cada integrante deve registrar seus próprios commits e demonstrar o caminho formulário → requisição HTTP → API → atualização da tela. As regras de estoque e confirmação devem ser combinadas entre os responsáveis por livros, pedidos e itens, sem tirar de cada um a responsabilidade pelo CRUD completo.
